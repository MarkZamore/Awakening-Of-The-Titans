# Правила Awakening Of The Titans

- Источник основы: Awakening Of The Titans, CurseForge project `1535260`, исходный файл `9427704`, версия `1.8.1`. Базовая платформа: Minecraft 1.21.1 / Fabric 0.19.5 / Java 21. ID `attack-on-titan`, опубликованный путь `Awakening Of The Titans` не менять при переименовании карточки или репозитория.
- Единственный редактируемый источник видимого имени — `library/content.json:name`. Производные названия манифеста/библиотеки/меню/публикации получают его через общий механизм подготовки; заголовок игры содержит ровно это имя без версии и статуса игры. Не вводить копии имени в конфиги или helper; `id`, `relativePath`, preset ID и repo URL имеют отдельное назначение стабильной идентичности.
- Последнее решение пользователя: сохранить базовые **You’re in Grave Danger** и Burnt с авторскими настройками; **не добавлять Gravestones/PneumonoCore** и не устанавливать два мода могил.
- `tools/overlay.json:requiredBaseMods` закрепляет реальные mod ID и CurseForge project ID Danny’s AOT, пяти аддонов, YIGD и Burnt. Проверка читает актуальные JAR, поэтому переименование файла не снимает требование; пропавший/дублирующийся ID или другой проект блокируют подготовку/публикацию. Запрещённые native ID — `gravestones` и `pneumonocore`, проверены по официальным JAR; `pneumono_gravestones` является slug, не ID. Происхождение и границы — `tools/base-mod-policy-evidence.json`.
- Проверять выбранные в лаунчере скины своего персонажа и пира, сохранение авторских превращений, стабильный portable UUID и прогресс после повторного входа. Миникарта и метки Xaero сохраняют мир, измерение и контекст Steam-хоста; личный `xaero` не включать в pack-owned слой. Синтетический профиль, локальный TCP и preflight не объявлять настоящим Steam-подключением или визуальной проверкой двух клиентов.
- Отдельное явное требование: камера от первого лица не находится внутри головы персонажа. Проверять обычную человеческую форму и ODM, превращение, выход из титана и респавн; авторские превращения, анимации и эффекты сохранять. Точечное исправление вводить только после доказательства фактического caller/site, не отключать механику или отображение тела целиком ради проверки.
- Открытие мира для друзей выполняется одним нажатием через общий e4steam без промежуточного окна настройки LAN. Мир должен появляться в мультиплеере самой игры через Steam, с настоящим именем мира и ником хоста из лаунчера; обычные UDP LAN-записи не подменяют этот сценарий. Любой участник может быть хостом.
- Публичные серверы не рекламировать: в авторском меню удалена только кнопка прямого подключения к публичному серверу. Сохранять обычную «Сетевую игру», миры Steam и ручные серверы игрока. Обязательный `publicServerPolicy` и `tools/server_menu_policy.py` проверяют все FancyMenu layouts; новый авторский shortcut блокирует подготовку. Не очищать личный `servers.dat` и не переносить эту настройку в C# лаунчера.
- Публикуемый манифест имеет schemaVersion 2 и требует общие возможности лаунчера `private-identity-asm-v1` и `registry-player-skins-v1`: изолированную ASM агента и загрузку скинов из точно подтверждённого реестра. Неизвестные профили сохраняют штатные проверки. Не убирать capabilities ради старого EXE и не вводить C#-исключение по имени сборки; сначала публикуется поддерживающий общий лаунчер, затем карточка.
- Сохранять pack-owned ограниченную диагностику четырёх перехваченных сетевых Throwable в latest.log. Для Fabric 1.21.1 реальный logger — `net.minecraft.class_2535`; при смене платформы повторить native-проверку. Политика/JVM selector/точный ownership находятся в overlay, проверяются до упаковки и повторно применяются при обновлении автора. Лаунчер XML при запуске не переписывает.
- Авторские выбранные ресурспаки сохранять через native missing-file-only YOSBR и config/yosbr/options.txt только с resourcePacks/incompatibleResourcePacks. Сохранять точные имена/порядок и обновлять projection из нового авторского options.txt при импорте. Не добавлять FOV, дальности, язык или клавиши и не владеть/переписывать личный root options.txt. Excalibur без отдельного решения не включать.
- Новый мир только с `attack_on_titan:paradis`; используется родная генерация `dannys-aot:paradis`. Не придумывать замену города/леса, не заменять её ванильной генерацией и не разрушать проверки native dimension ID. Появление в Парадизе принадлежит GlobalSpawn/данным сборки, а не лаунчеру. Существующие миры не блокировать.
- Любое обновление upstream обязано повторно применить overlay этой поставки и пройти его проверку. Исторический upstream lock не восстанавливает активную производную сборку. Не обходить fail-closed проверки helper, ownership, обязательных конфигов или библиотечных ссылок.
- Активные JAR и locks изменяет один назначенный владелец последовательно. Все исходные версии и SHA256 фиксировать до изменений; замены BASE JAR описывать с причиной и рисками registry ID. Не обновлять общие библиотеки массово и не менять происхождение NEW на BASE при очередном обновлении.
- Для каждого нового/обновлённого JAR проводить Safety-аудит: world/inventory mutation, native permission gates, caster/owner, отложенные действия и обе стороны LAN. Не переносить политику ATM9 без отдельного решения. Не выдавать native claim-проверку одного пути за защиту всего мода.
- Все контентные настройки, JVM-параметры, исправления и ресурсы по возможности принадлежат сборке. Не добавлять launcher-side правила по имени сборки или мода. Не вводить свои пределы render/simulation/shadow distance.
- `library/mod-pages.json` покрывает все активные mod ID, включая вложенные. Приоритет — официальная CurseForge-страница именно этого проекта, затем Modrinth, затем источник автора. Для встроенного компонента без отдельной страницы использовать источник содержащего проекта и документировать исключение в `library/README.md`; не подставлять одноимённый чужой мод. Недоступный авторский адрес хранить с `available: false`.
- Ссылки, addon-отношения и отделение технических библиотек обновлять по фактическим JAR. Зависимость сама по себе не доказывает addon-отношение. Счётчик модов не равен числу файлов JAR.
- Рано запускать согласованные полный клиент, dedicated server и вход в независимый QA-мир; повторять после существенных изменений. Проверять реальный native renderer, registry и mixin failures; не отключать молча эффекты/шейдеры ради запуска. Dedicated Done, packer и офлайн bytecode не являются полным игровым PASS.
- Статус в `TESTING-STATUS.md` должен называть фактически проверенную ревизию и оставшиеся ERROR. Не обещать сохранность старых миров без проверки. Личные миры и игровые экземпляры не использовать как стенд; сырые логи и личные пути не публиковать.
- В итоговом отчёте перечислять pack-owned изменения и всё оставшееся в лаунчере с причинами; если launcher-side исключений нет, говорить это прямо. Публиковать payload до манифеста; новую карточку каталога добавлять только после успешной проверки release.

## Автоматический список серверов

- Лаунчер предназначен для миров через Steam. Сохранять отключёнными авторские публичные server seeds и кнопки прямого подключения; личные servers.dat игрока не читать и не очищать.
- Обязательный read-only gate перед загрузкой assets: `python tools/public_server_policy.py --pack . --manifest dist/pack-manifest.json`. Он закрепляет полный проверенный состав из `tools/public-server-policy.json`, проверяет текстовые входы и отсутствие поставляемых NBT-списков.
- После авторского обновления изменённый, новый или удалённый JAR/конфиг/скрипт/ресурс блокирует выпуск до повторной проверки seeding и меню. Сохранять штатный отключающий конфиг/слой сборки; не принимать новый pin автоматически и не удалять gate ради обновления. Общий инструмент и его тесты: LANMinecraft, `tools/PackData/ServerPolicy` (940a562).
- Эти проверки не объявлять новым игровым прогоном. Если новый движок или мод изменяет native hooks, проверять фактический целевой runtime до явного обновления reviewedInventorySha256.
