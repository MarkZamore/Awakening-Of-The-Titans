# Общие механизмы лаунчера

Игровые JAR, генератор Danny’s AOT, измерения, скины превращений и настройки механик не изменены этими исправлениями. Название не используется как условие в C#. Собственные игровые изменения сборки описаны в её overlay; ниже перечислена общая инфраструктура запуска, которую требуется оставить в лаунчере.

## Изоляция ASM у двух Java-агентов

Настоящий полный клиент с Fabric 0.19.5 и опубликованным лаунчером 438 остановился в `LoaderUtil.verifyClasspath`: официальный ASM загрузчика и встроенный публичный `org.objectweb.asm` агента идентичности одновременно были видны system class loader. Bootstrap-only split уже существовал, но не убирал второй system-classpath ресурс. Агент уведомлений содержал такой же публичный пакет и потребовал того же исправления при проверке полного производственного набора агентов.

Сборщики `Program/IdentityAdapters/Common/Build-IdentityAdapter.ps1` и `Program/NoticeOverlay/Build-NoticeOverlay.ps1` теперь используют build-only `RelocateAsm.java`. Закреплённые исходные ASM 9.8 и их SHA256 не заменяются. Runtime копии получают разные закрытые пакеты `minecraft.portable.internal.asm` и `minecraft.portable.notice.internal.asm`. В bootstrap JAR по-прежнему находятся только не зависящие от ASM hooks. Build tool не попадает в runtime.

Это нельзя исправить настройкой контентного мода или датапаком: агенты принадлежат процессу лаунчера и попадают в classpath до инициализации Fabric. Замена версии загрузчика, отключение его strict guard, удаление агента идентичности или уведомлений не используются. Исправление общее для всех пакетов, запускаемых с этими агентами.

Новая общая возможность манифеста `private-identity-asm-v1` требует схему 2. Старый лаунчер штатно отклоняет неизвестную возможность до загрузки поставки и предлагает обновиться. Это контракт фактически подтверждённой совместимости, а не список сборок в C#.

## Очередь закрытия native LAN-экрана

`IdentityAdapterMappingService.AddLanPublishProperties` прежде искал только `BlockableEventLoop.schedule(Runnable)`. Minecraft 1.21.1 называет настоящую всегда отложенную очередь `tell(Runnable)` (`method_18858`). Fallback `Executor.execute` может выполнить действие внутри оставшейся части `init`.

Поиск теперь предпочитает `schedule`, затем `tell` с точным дескриптором. Существующая native-init публикация, проверки авторского/e4steam экрана и правила открытия мира сохранены. Исправление относится к общей инфраструктуре Steam/LAN лаунчера и её жизненному циклу. Датапак не управляет клиентским screen init; изменение FancyMenu или авторского генератора не решает порядок native callbacks. Отдельного условия по имени сборки или контентному моду нет.

## Канонический заголовок окна

`WindowTitleMappingService` умел проверять named `net/minecraft/client/Minecraft.createTitle` и SRG `m_91270_`, поэтому для настоящего Fabric 1.21.1 отключал заголовок, хотя канонический текст уже передавался правильно. Реальная фабрика исходного JAR — `fgo.bd()String`; после ремапа — `net.minecraft.class_310.method_24287()String`.

Сервис теперь использует существующие, привязанные к версии Minecraft mappings, сверяет header и таблицу методов настоящего source JAR и передаёт точные aliases в прежний Java preflight/return transformer. Меняется только результат фабрики на переданное каноническое имя. Другие заголовки, соединения, игровые статусы и native методы не подменяются; отдельного setter/timer, pack-specific файла или копии названия в C# нет.

Источник имени остаётся декларативным свойством сборки. Исправление отображения сохраняется в общей реализации лаунчера: именно она уже владеет единым заголовком всех поддерживаемых платформ и final producer hook. Настройка контентного меню не предоставляет такого же общего поведения при подключении, отключении и открытии LAN.

## Скин настоящего удалённого игрока

Два настоящих клиента с разными переносимыми UUID показали конкретный дефект 439: собственные скины загружались на GPU правильно, но известный удалённый игрок в той же точке мира получал vanilla default с `textureUrl=null`. Identity registry, профиль сущности и SkinService были правильными. Это отдельная проверка реального пира; неизвестный контрольный `PlayerInfo` её не заменяет.

Причина находится в общей цепочке выбора скина. Fallback `BuildSkinsOnly` сохранял authlib, но отбрасывал mapped `PlayerInfo`; Java transformer дополнительно связывал его с выключенным семейством login hooks. Minecraft 1.21.1 требует secure skin для пира и отвергал подготовленный unsigned скин. Собственный игрок не предъявляет это требование, поэтому один клиент проблему не обнаруживал.

Независимая возможность `playerInfoSkinEnabled` сохраняет только проверенную native skin family: raw `fzq.a` и runtime `class_640.method_52803` для lookup, `class_640.method_52806` для выбора, точные raw/intermediary дескрипторы и accessors `PlayerSkin`. Неизвестные/неполные mappings не угадываются. Preflight проверяет, что изменились ровно два нужных static метода, а native return type действительно имеет `secure()` и `textureUrl()`.

Уже существующий registry guard допускает unsigned skin только с точным URL из registry. Signed native скины, неизвестные профили, другие loopback URL, подменённый hash и посторонние адреса сохраняют штатное поведение. Глобальная проверка secure skins не отключается. Авторские skin mixins Danny’s AOT и превращения остаются активными.

Эта часть принадлежит общему SkinService/Java-agent протоколу лаунчера: registry и локальный HTTP endpoint создаются его процессом. Она применяется ко всем поддерживаемым runtime с проверенной native family, без правила по имени сборки. Возможность поставки `registry-player-skins-v1` защищает установку от запуска на лаунчере без этого исправления. Фактический PASS удалённого GPU-скина требует обычного запуска исправленного клиента; bytecode preflight и тест JVM отдельно его не подтверждают.

Исправление опубликовано в общем лаунчере **440**, revision `14e83c8`. После штатного сохранения и обычного перезапуска два настоящих клиента подтвердили собственный и удалённый скин в обоих направлениях: SLIM, 2259 непрозрачных RGB-пикселей, и classic/WIDE, 4096 пикселей, обе GPU-текстуры 64×64, ноль RGB-расхождений. Проверены реальные удалённые player entities и native PlayerInfo, точные registry URL и независимые UUID. Неизвестный контрольный профиль не получил локальный скин. Авторские skin mixins оставлены активными. Лаунчер прошёл обязательные Release 670/670 и Adapters 253/253 без пропусков.

Это native программная/GPU проверка двух процессов с локальным TCP. Она не объявляет настоящие Steam authentication/P2P/friend discovery или визуальную CUA-оценку двух окон выполненными.

## Что дополнительно не переносилось из других сборок

В этой сборке установлен Xaero Minimap, а не JourneyMap. Его настоящий формат, ID мира и размерные папки проверены отдельно; адресные Forge/JourneyMap skin, dimension или Safety-инъекции не добавлялись. Native скин берётся существующей общей цепочкой `SkinService` и identity adapter. Авторские skin mixins Danny’s AOT остаются активными.

Компиляция и Java preflight сами по себе не доказывают полный клиент, визуальный скин, два клиента, Steam или сохранение прогресса. Фактические результаты и границы проверки находятся в основном `TESTING-STATUS.md`; инструменты этого каталога явно различают native proof, локальную протокольную симуляцию и настоящий Steam.
